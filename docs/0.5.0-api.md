# Fetch API decisions for 0.5.0

Review date: 2026-10-09. Baseline: published `@askrjs/fetch@0.4.2` and
`origin/develop` commit `fd6d9c52ff4cfca07a2457780a171e0502158c88`.
The package remains version 0.4.2 during preparation; this inventory describes
its prepared breaking surface, not a published 0.5 package.

The 54 published names become 31: root 47 -> 26 (21 values and five types),
middleware 7 -> 5. Curated barrels prevent reachable implementation aliases
from becoming root imports. No deprecation shims are retained.

## Export-map decisions

| Key                   | Decision | Consumer reason                                                                                          |
| --------------------- | -------- | -------------------------------------------------------------------------------------------------------- |
| `.`                   | KEEP     | Request contracts, clients, codecs, result handling and typed authoring extensions.                      |
| `./middleware`        | KEEP     | README and installed consumers import the five optional middleware factories without expanding the root. |
| `./package.json`      | KEEP     | Package identity/version/export metadata read by installed consumers and release tooling.                |
| `./capabilities.json` | KEEP     | CLI capability discovery and published package capability metadata.                                      |

No export-map key is removed. Source modules (`types`, `dsl`, `client`,
`codecs`, `middleware-impl`) remain private package paths.

## Consumer search

The organization review searched sibling packages, examples, package docs,
CLI templates/generator output, generated starter fixtures, tests and website
prose/API definitions. Direct source import inventories alone miss generated
strings: `askr-cli/src/generate/generator.ts` emits `ClientOptions`,
`createClient`, `defineApi`, method factories and codecs. That type is retained.
Its generated calls and the website `usage-guide.ts` examples keep their current
imports. The package's existing typed codec, validator and middleware assertions
supply concrete authoring contracts for the retained extension types.

No external named import uses the 23 removed names in the reviewed source or
generated templates. The package's own `pathNames` characterization now imports
the private DSL implementation rather than promising a consumer lexer API.
Website generated API data is still a 0.4 snapshot and must be regenerated from
the complete coordinated 0.5 candidate set before API issue #56 is closed.

## Migration examples

```ts
import { createClient, createFetch, defineApi, get, text } from "@askrjs/fetch";
import type { ClientOptions, FetchResult, Middleware } from "@askrjs/fetch";
import { retry, telemetry } from "@askrjs/fetch/middleware";

const api = defineApi({ read: get("/health").returns(text()) });
const client = createClient(api);
type Client = typeof client;
type ReadResult = Awaited<ReturnType<typeof client.read>>;
type Call = Parameters<ReturnType<typeof createFetch>>[0];
type Context = Parameters<Middleware>[0];
type RetryConfiguration = Parameters<typeof retry>[0];
type Hooks = Parameters<typeof telemetry>[0];
```

Input parameter/metadata objects and returned builders/descriptors continue to
infer their full structural types. Removing their named aliases does not weaken
inference, status discrimination, path requirements or schema transformations.
Do not import private `dist` modules as replacements.

## Validation boundary

Source public-surface checks freeze the runtime names. The real installed
consumer imports both entrypoints, verifies exact runtime/type names and export
keys, rejects every removed import and all private module paths, and retains
schema inference, required path parameters and replayed body behavior. These
checks run in normal three-OS CI. The complete packed 0.5 package set, generated
client and refreshed website data remain coordinated release gates.
