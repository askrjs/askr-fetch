# Fetch hardening for 0.5.0

Executed on 2026-10-09 against the prepared API contraction. The package manifest
is still 0.4.2; this is preparation evidence, not coordinated 0.5.0 publication.

## Inspected and exercised contracts

The existing 38-case `tests/fetch.test.ts` suite was inspected at assertion level
and executed. Its existing coverage already checks middleware ordering and
telemetry exception reporting, all codecs with standard Request/Response bodies,
validation error identity, literal status decoding, request content selection,
concurrent request isolation, PUT/DELETE replay after HTTP and network failures,
unsafe POST exclusion, deadline boundaries, Retry-After validation/clamping,
consumed and streaming request bodies sent once, and response stream abort,
timeout and cleanup. These cases were retained rather than copied.

`tests/retry-cancellation.test.ts` adds 20 cancellation/ownership cases. Substituting the
original client and middleware implementations from develop
`fd6d9c52ff4cfca07a2457780a171e0502158c88` produces **18 failures and 2 passes**.
The prepared implementation passes all 20. The two passing characterizations
cover already-aborted calls and abort during pending retry backoff.

| Boundary                                            | Assertions and outcome                                                                                                                                                                                                                                                            |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backoff ready, continuation pending                 | Abort after the timer resolves prevents another middleware/transport attempt; timers and caller/backoff listeners are removed. Confirmed defect, fixed.                                                                                                                           |
| Async credentials finish after cancellation         | Caller abort and timeout retain their distinct result and cause; transport never starts. Confirmed defect, fixed.                                                                                                                                                                 |
| Async middleware remains pending                    | Abort/timeout settle before token completion; subsequent middleware/transport never run after late resolve or reject; late rejection is consumed. Four regressions, confirmed defect, fixed.                                                                                      |
| Custom transport remains pending                    | Abort/timeout settle before transport completion; late rejection is consumed; a late stream response is neither cloned nor locked and cannot replace the result. Four regressions, confirmed defect, fixed.                                                                       |
| Timeout during retry after backwards clock movement | The controller's timeout cause remains `timeout`, with no second transport attempt or pending timers. Confirmed classification defect, fixed.                                                                                                                                     |
| Undelivered stream                                  | Abort/timeout while outward middleware waits, and outward middleware failure, cancel the source exactly once and remove timers/listeners. Source-cancel rejection preserves the primary result without an unhandled failure. Four regressions, confirmed ownership defect, fixed. |
| Buffered body interrupted                           | Abort and timeout preserve the exact cause, original response identity, status 200 and request URL. Confirmed classification defect, fixed.                                                                                                                                       |
| Malformed non-success responses                     | Invalid JSON at 400, incompatible media type at 415 and missing codec at 503 preserve `decode`, error class, original response, status, headers and URL. Three passing characterization cases; no defect found.                                                                   |
| One-shot response streams                           | Existing Node tests protect signal/timeout ownership through consumption. Packed browser probes prohibit cloning and verify body identity, bytes and cleanup after close. No new defect found.                                                                                    |

The client owns a single cancellation wait around dispatch. Cancellation settles
that wait, and freshness checks at queued middleware, transport and decode
continuations prevent late work from starting the next package-owned operation.
Both dispatch handlers remain attached to consume late rejection. Arbitrary
providers and custom transports still own cancellation of their internal work;
the client cannot stop an uncooperative promise. Streams that cannot be delivered are cancelled; cleanup failures cannot replace
the primary call outcome. Returned response streams keep
the existing timeout/signal ownership until consumption finishes.

## Packed and cross-runtime qualification

`npm run test:installed` creates a fresh consumer from `npm pack`, installs the
supported schema dependency without forcing peers, and exercises auth, schema
validation and replayable request bodies. It verifies every runtime export, all
31 declaration exports with the TypeScript compiler API, 23 removed imports,
private subpath rejection and required endpoint/path inference. This probe and
coverage reporting run in the ordinary Linux, Windows and macOS CI matrix.
The first hosted Windows run exposed direct `npm.cmd` spawning in the existing
probe. The probe now invokes npm's JavaScript CLI through Node, without a shell.

Separate packed-browser probes served the installed ESM JavaScript directly over
local HTTP, without bundling or a development optimizer. All nine cases passed in
each of Chromium, Firefox and WebKit: retry-ready cancellation, async-auth abort,
async-auth timeout, buffered-decode abort, buffered-decode timeout, undelivered stream abort/timeout/middleware failure and one-shot
stream close. **27 candidate cases passed.** The registry 0.4.2 baseline failed
the eight cancellation/ownership probes in every engine (**24 failures**) and passed the
three one-shot stream characterizations. Auth probes assert settlement before
the held token finishes. Transport is controlled; this does not certify network
capacity, real credential providers or application integration.

The tested compiled client has SHA-256
`f8a53a81be88bf7cbfae1cc4ae4d76e44c24ada62e48d39b477aafa55864e4ac`.
The complete browser fixture, package/file hashes, results and failed harness
diagnostics are retained in the release evidence directory. Initial Vite-based
runs were rejected as qualification because optimizer reloads destroyed the page
context; the accepted matrix uses the direct static server.

## Coverage and validation

`npm run check` runs formatting, lint/types, unit tests, coverage, build, packed
consumer, publint and pack contents. There are **63 unit cases**: the original
38, 20 cancellation/ownership regressions/characterizations, three malformed non-success
characterizations and two exact runtime-surface cases. Unit coverage includes
every `src/**/*.ts` file; pure type/barrel files have no executable counters.
Packed/browser probes provide additional behavioral evidence and are not part
of the source coverage percentage.

still require coordinated qualification. This patch alone does not complete
the broader release or Fetch API issue #56.
